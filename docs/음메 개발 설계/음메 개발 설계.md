# 음메 개발 설계

**목표:** 4인 팀원이 코드 충돌 없이 각자 독립적으로 개발할 수 있도록 **중앙 통제(app.py)**와 **최소 인터페이스** 규격을 정의한다.

## **1. 개발 원칙 및 충돌 방지 룰**

### **1) 1인 1파일 원칙 (작업 영역 분리)**

모든 개발자는 `modules/` 안의 **자신이 맡은 파일 1개만 수정**한다. 공통 진입점(`app.py`)과 공통 데이터 규격(`models.py`)은 개발 리드가 총괄 관리한다.

| 담당자 | 파일 경로 | 주요 역할 |
| --- | --- | --- |
| **이규민** | `modules/menu_list.py` | 메뉴 목록 표시, 음식 추가(사진/이름)/삭제, 선택 체크박스 UI |
| **장산** | `modules/draw_engine.py` | 순수 추첨 계산 로직 (주사위 굴리기) |
| **석혜인** | `modules/effects.py` | 추첨 진행 중 연출 캡슐화 (룰렛/애니메이션 등) |
| **김가연** | `modules/result_view.py` | 당첨 결과 카드 UI 렌더링 및 PNG 카드 다운로드 기능 |
| **개발 리드** | `app.py`, `models.py` | 공통 데이터 규격 관리 및 전체 실행 흐름 조율 (GameManager) |

### **2) 모듈 간 직접 참조(import) 절대 금지**

- `menu_list.py`, `draw_engine.py`, `effects.py`, `result_view.py`는 **서로를 절대 import 하지 않는다.**
- 모든 데이터 전달과 실행 순서는 중앙 지휘소인 `app.py`가 통제한다.

## **2. 공통 데이터 규격 (`models.py`)**

데이터 무결성을 위해 주고받는 기본 단위는 파이썬 `dataclass`를 사용한다.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Food:
	id:str # 고유 식별자 (기본 메뉴는 '음식 이름의 영어 발음'과 같은 규칙으로 선제 설정, 추가 메뉴는 uuid 통해 생성)
  name:str # 음식 이름
  image_path:str="assets/images/default.png" # 음식 사진 경로 (사진 미등록 시 기본 아이콘)
```

### **중앙 데이터 저장소 (Registry)**

- 원본 데이터(`dict[str, Food]`)는 `app.py`의 `st.session_state`에 **단 하나만 보관**한다 (Single Source of Truth).
- 메뉴 추가/삭제(쓰기)는 오직 `menu_list.py`를 통해서만 발생하므로 데이터 충돌이 없다.
- 어디서든 ID로 원본을 꺼낼 수 있는 단일 함수를 제공한다:

```python
def get_food(food_id:str)-> Food:
		return st.session_state.registry[food_id]
```

## **3. 모듈별 인터페이스 규격 (함수 입출력 계약)**

<aside>

내부 알고리즘은 각 개발자의 재량으로 자유롭게 구현

단 **함수이름**, **전달 인자**, **반환값**은 아래 규격을 반드시 지킨다

</aside>

| 대상 파일 | 함수 | 입력 | 출력 |
| --- | --- | --- | --- |
| `menu_list.py` | `load_default_foods()` | 없음 (`None`) | `dict[str, Food]` (all_foods) |
| `menu_list.py` | `render_menu(all_foods)` | `list[Food]` | `list[str]` (selected_ids) |
| `draw_engine.py` | `draw(selected_ids)` | `list[str]` | `str` (selected_id) |
| `effects.py` | `play()` | 없음 (`None`) | 없음 (`None`) |
| `result_view.py` | `render_result(selected_food)` | `Food` | 없음 (`None`) |

## **4. 중앙 제어 및 상태 유지 (`app.py`)**

Streamlit은 사용자가 버튼을 클릭할 때마다 스크립트 전체를 재실행(Rerun)하므로, `st.session_state`를 이용해 화면과 상태를 유지한다.

```python
import streamlit as st
from models import Food
from modules import menu_list, draw_engine, effects, result_view

# 1. 중앙 데이터 저장소 최초 초기화 (세션 유지)
if "registry" not in st.session_state:
    st.session_state.registry = load_default_foods()    # 기본 음식 로드 (menu_list.py 내부 선언)
if "selected" not in st.session_state:
    st.session_state.selected = None
    
st.title("🐮 음메 - 오늘 뭐 먹지?")

# 2. 메뉴 목록 UI 표시 및 선택된 ID 수집
selected_ids = menu_list.render_menu(list(st.session_state.registry.values()))

# 3. [뽑기] 버튼 클릭 시 동작 시퀀스
if st.button("오늘의 메뉴 뽑기!", disabled=(len(selected_ids) == 0)):

	# 1단계: 순수 추첨
    selected_id = draw_engine.draw(selected_ids)
    selected_food = st.session_state.registry[selected_id]

	# 2단계: 연출 재생 (캡슐화 함수 1회 호출)
    effects.play()

	# 3단계: 당첨 결과 세션에 보관 (이후 다운로드 클릭 시에도 결과 유지)
    st.session_state.selected = selected_food
    
# 4. 결과 출력 (세션에 당첨 데이터가 있으면 항상 표시)
if st.session_state.selected is not None:
    result_view.render_result(st.session_state.selected)
```
