## 1. 개요 및 목적

- 앱이 처음 목록을 그릴 때, 코드 안 시드로 기본 메뉴를 만들어 이름과 이미지를 보여 준다. 체크된 메뉴 ID를 돌려준다.
- 사용자가 새 메뉴를 입력해 목록에 추가하고, 항목마다 삭제할 수 있다. 추가할 때는 이름과 사진을 둘 다 받는다.
- 추가·삭제된 목록은 세션에 남긴다. 화면이 다시 그려져도 기본 시드로 되돌리지 않고, 추첨 엔진에는 체크된 ID만 넘긴다.
- 관련 파일은 `menu_list.py`, `app.py`다. `models.py`는 수정하지 않고, 룰렛·결과창·이펙트 모듈은 import하지 않는다. `menu_list.py`에서 추첨 함수를 호출하지 않는다.
- `Food` 필드는 `id`, `name`, `image_path`만 쓴다. 한식/중식/일식/양식은 시드 안에서만 구분한다. `default.png`는 기본 시드용이며, 추가 메뉴에는 쓰지 않는다.
- 목록 유지는 `st.session_state`만 쓴다. 메뉴 목록을 파일로 저장하지 않고, 새 라이브러리도 쓰지 않는다.

## 2. 입·출력 명세 (I/O)

### 📥 입력 데이터 (Input)

- `load_default_foods()`: 입력 없음. 외부 DB나 파일을 읽지 않는다.
- `render_menu(all_foods: list[Food])`: 화면에 그릴 `Food` 리스트. `list(registry.values())`처럼 사전 값에서 만든다.
- `add_food(registry, name, image_path)`
    - `registry: dict[str, Food]`: 현재 목록
    - `name: str`: 사용자가 입력한 이름
    - `image_path: str`: 업로드한 사진 경로
- `remove_food(registry, food_id)`
    - `registry: dict[str, Food]`
    - `food_id: str`: 지울 항목의 ID
- 화면: 이름 입력칸, 사진 파일(png, jpg, jpeg), 추가 버튼, 항목마다 삭제 버튼, 추첨용 체크박스
- 세션에 `registry` 키가 있는지. 없을 때 넣을 값은 `load_default_foods()`의 `dict[str, Food]`다.
- `Food` 필드

| 필드 | 타입 | 의미 | 예 |
| --- | --- | --- | --- |
| `id` | `str` | 기본 메뉴는 음식 이름 영어 발음. 추가 메뉴는 uuid. dict의 키와 같다 | `"bibimbap"` |
| `name` | `str` | 화면에 보일 이름 | `"비빔밥"` |
| `image_path` | `str` | 이미지 파일 경로. 기본 시드에 전용 사진이 없으면 `assets/images/default.png` | `"assets/images/bibimbap.png"` |

| 키 | 타입 | 언제 생기나 |
| --- | --- | --- |
| `st.session_state.registry` | `dict[str, Food]` | 세션에 이 키가 없을 때만 `load_default_foods()`로 만든다 |

### 📤 출력 데이터 (Output)

- `load_default_foods() -> dict[str, Food]`: `id`를 키로 하는 메뉴 사전. `app.py`가 세션에 `registry`가 없을 때 이 값으로 초기화한다.
- `render_menu(...) -> list[str]`: 이름과 이미지를 그린 뒤, 체크된 메뉴 ID. 선택된 항목이 없으면 `[]`. 이 값이 추첨 입력이다.
- `add_food(...) -> Food`: 새로 만든 메뉴. `registry[id]`에 넣는다. 거절되면 `Food`를 만들지 않고 `registry`도 바꾸지 않는다.
    - `id`: 표준 라이브러리 `uuid`. 이름 문자열을 키로 쓰지 않는다.
    - `name`: 앞뒤 공백을 제거한 문자열.
    - `image_path`: `assets/images/{uuid}.{확장자}`
- `remove_food(...)`: 반환값 없음. `registry`에서 그 키만 삭제한다. 없는 키면 목록을 바꾸지 않는다.
- 이미 `registry`가 있으면 그 dict를 그대로 쓴다. 추가된 `Food`의 `image_path`도 이 dict 안에 남는다. 사진 파일 자체를 세션 저장으로 다루지 않는다.
- `render_menu`는 체크된 ID `list[str]`를 반환한다. 선택이 없으면 `[]`다. `app.py`는 이 목록 길이가 0이면 뽑기 버튼을 비활성화하고 `draw_engine.draw`를 호출하지 않는다. 버튼이 눌린 뒤에만 `selected_ids`를 `draw_engine.draw`에 넘긴다. 당첨 메뉴 조회는 `app.py`가 `registry[selected_id]`로 한다.
- 최소 조건은 카테고리당 2개다. 시드에는 아래 표를 넣는다.

## 3. 핵심 처리 로직 (Logic)

- 내부에서 순차적으로 일어나는 처리 흐름을 단계별로 정리합니다.
1. **유효성 검사**:
    - 시드 `id`는 음식 이름 영어 발음이고, 목록 전체에서 겹치면 안 된다. 같으면 dict에서 앞 항목이 덮인다.
    - 같은 발음은 하나만 둔다. 예를 들어 우동은 일식 `udon`만 넣는다.
    - 기본 시드에서 사진 경로를 따로 적지 않은 항목은 `assets/images/default.png`를 쓴다.
    - 추가 버튼을 누르면 이름 앞뒤 공백을 제거한다. 이름이 비었거나 사진이 없으면 추가하지 않는다.
    - 확장자가 png, jpg, jpeg가 아니면 추가하지 않는다. 중복 검사는 `Food.name`으로만 한다. 시드에 `name`이 `비빔밥`인 항목이 있으면 입력 이름 `비빔밥`은 거절한다. `id` `bibimbap`과 `name` `비빔밥`은 같은 음식의 다른 필드일 뿐이고, `id`와 입력 이름을 비교해 중복을 판단하지 않는다.
    - `app.py`가 시작할 때 `registry` 키가 세션에 있는지 확인한다. 체크된 ID가 없으면 `render_menu`는 `[]`를 반환하고, `app.py`는 뽑기 버튼을 비활성화해 `draw`를 호출하지 않는다. 목록 전체나 기본 시드로 대체하지 않는다.
2. **핵심 연산 / 처리**:
    - `load_default_foods` 안에 시드를 `(id, name)`으로 둔다. 구분은 주석이나 구역으로만 표시하고, `Food` 필드로는 넣지 않는다.
    - 목록을 돌며 `Food(id, name, "assets/images/default.png")`를 만든다. 전용 사진이 있는 항목만 경로를 바꾼다.
    - `id`를 키로 한 `dict`를 만든다. 키와 `Food.id`는 같다.
    - 추가 사진은 `assets/images/{uuid}.{확장자}`로 저장한다. 저장에 실패하면 목록에 넣지 않는다. `id`는 그 `uuid`로 만들고, 기존 키와 겹치면 덮어쓰지 않고 다시 만든다.
    - `Food(id, name, image_path)`를 `registry[id]`에 넣는다. 삭제 버튼은 그 행의 `food_id`만 `remove_food`에 넘긴다. 목록을 바꾸는 코드는 `menu_list.py`에만 둔다.
    - 세션에 `registry` 키가 없으면 `load_default_foods()` 결과를 넣는다. 키가 있으면 그 dict를 그대로 쓰고 기본 시드로 덮지 않는다. 추가·삭제는 이 dict를 직접 수정한다.
    - Streamlit이 버튼을 처리하고 스크립트를 다시 실행해도, 같은 브라우저 세션 안에서는 기본 시드 로드로 돌아가지 않는다.

3. **결과 가공 및 반환**:
    - `load_default_foods`는 시드 dict를 반환한다. `app.py`는 `registry`가 없을 때만 이 값으로 세션을 초기화한다.
    - `render_menu`는 리스트를 순서대로 돌며 이름과 `image_path` 이미지를 출력하고, 체크된 ID `list[str]`를 반환한다.

    - 뽑기 버튼이 눌린 뒤에만 `app.py`가 그 ID 목록을 `draw_engine.draw`에 넘긴다.

## 4. 예외 및 에러 처리 (Edge Cases)

- [ ]  **이미지 파일이 없는 경우:** 목록 출력은 계속한다. 해당 항목은 이름만 보여 주거나, 파일이 있는 `default.png`로 대체한다. 예외로 앱이 멈추면 안 된다.
- [ ]  **default.png도 없는 경우:** 이미지는 생략하고 이름 목록은 남긴다.
- [ ]  **메뉴 목록이 비어 있는 경우:** `all_foods`가 빈 리스트면 “메뉴가 없습니다”처럼 안내만 출력한다. 인덱스로 접근해 에러를 내지 않는다. 입력칸, 사진 업로드, 안내 문구는 남긴다.
- [ ]  **시드 ID가 같은 경우:** 앞 항목이 덮이므로, 시드를 넣을 때 ID를 서로 다르게 둔다.
- [ ]  **외부 의존이 없는 경우:** `load_default_foods`는 인자, 파일 읽기, 다른 기능 모듈에 의존하지 않는다. 시드만으로 항상 같은 dict를 만든다.
- [ ]  **추가 입력이 잘못된 경우:** 공백만 입력하거나 빈 이름, 사진 없음, 허용되지 않은 확장자, 사진 저장 실패, 같은 이름이면 거절한다. `default.png`로 대체하지 않고 기존 목록은 유지한다.
- [ ]  **추가 때 키가 겹치는 경우:** 기존 `Food`를 덮어쓰지 않는다. 세션의 다른 항목도 지워지지 않는다.
- [ ]  **없는 항목을 삭제하는 경우:** 세션 dict는 그대로다. 예외가 나서 세션이 초기화되면 안 된다.
- [ ]  **목록이 비어도 세션은 남는 경우:** `registry` 키는 세션에 남긴다. 키를 지우면 다음 실행에서 기본 메뉴가 다시 로드된다.
- [ ]  **체크된 ID가 없는 경우:** `render_menu`는 `[]`를 반환한다. `app.py`는 뽑기 버튼을 비활성화하고 `draw_engine.draw`를 호출하지 않는다.
- [ ]  **브라우저를 닫거나 서버를 다시 켜는 경우:** 세션은 사라진다. 이 경우까지 파일로 저장하지 않는다.
