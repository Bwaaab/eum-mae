## 4. 논의 및 결정 사항 (안건별)

### [3주차] 안건 1:

- **논의 내용:** 메뉴 선택 장애를 해결하는 파이썬 기반 메뉴 뽑기(가챠) 웹 앱 기능 명세 및 역할 분담
- **결정 사항:**
    1. 메뉴 풀 관리 (이규민)
    2. 가챠 기능 (장산)
    3. 결과 화면 및 저장 (김가연)
    4. 시각 연출 및 이펙트 (석혜인)
- **결정 이유:** 각 팀원의 역할 구분을 명확히 하여 독립적인 이슈 발행 및 병행 개발이 가능하도록 설정함.

### [3주차] 안건 2:

- **논의 내용:** 코드 리뷰, PR 관리 및 메인 브랜치 병합 프로세스 정립
- **결정 사항:**
    - 세부 작업 단위별 Issue 작성 후 개별 브랜치 작업
    - Commit 및 PR 시 이슈 번호 명시 (`Closes #이슈번호`)
    - 이규민(리뷰/품질)의 코드 검수 후 승인
    - 장산(개발 리드)이 최종 `main` 브랜치 병합 (Merge)
- **결정 이유:** 코드 품질을 유지하고 충돌 방지 및 히스토리 관리의 효율성을 높이기 위함.

### **[4주차] 안건 3: 프로젝트 제안서 최종 검토 및 문서 브랜치(`docs/meeting`) 수립**

- **논의 내용:** 제안서 오탈자 수정, 라이선스(MIT) 추가 및 회의록 관리 디렉터리(`meetings/`) 운영 규칙 확인
- **결정 사항:**
    - 제안서 내 도구(소스트리), 소통 채널(카카오톡) 일치 작업 완료
    - 초기 문서 PR(#6) 병합 후, 문서 담당자는 `docs/meeting` 브랜치를 생성하여 회의록 커밋
- **결정 이유:** 모든 변경 사항을 `main`에 직접 올리지 않고 개별 브랜치에서 관리하는 규칙을 준수하기 위함.

### **[4주차] 안건 4: 프로젝트 제안서 발표 역할 분담**

- **논의 내용:** 금요일 제안서 발표 시 전원 참여 요건 충족을 위한 목차 분담
- **결정 사항:**
    - 1. 팀 소개 & 2. 프로젝트 소개: 석혜인
    - 3. 기능 소개: 김가연
    - 4. 예상 결과물: 장산
    - 5. 계획 및 협업 일정: 이규민
- **결정 이유:** 담당 영역과 제안서 흐름에 맞추어 각자 맡은 역할을 가장 효과적으로 설명할 수 있도록 분배함.
